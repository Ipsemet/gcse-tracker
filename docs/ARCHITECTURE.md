# Architecture

## The spec spine

```
Subject (OCR J277)
└── SpecUnit        1.1  Systems architecture
    └── SpecTopic   1.1.1 Architecture of the CPU
        └── SpecPoint 1.1.1a "The purpose of the CPU: the fetch–decode–execute cycle"
```

The **SpecPoint** is the atom. It is the unit of:

- **content attachment** — every note section, flashcard and question lists the spec points it covers
- **mastery** — one `MasteryRecord` per spec point
- **planning** — the planner ranks work by which spec points are weakest
- **reporting** — "62% of the spec covered" means something because the denominator is the real spec

Ids are generated by the build tool from the board's own codes (`j277.1.1.1a`), never hand-written,
so they cannot drift or be mistyped.

## Data flow

```
content/subjects/<id>/*.mjs      authored, human-readable
        │
        ▼  tools/build-content.mjs — zod validation, id generation, cross-reference checks
app/public/content/<id>/*.json   compiled, validated
        │
        ▼  lib/content.ts — fetch + memoise; service worker caches stale-while-revalidate
Zustand stores (useContent, useProgress)
        │
        ▼
React routes
        │
        ▼  lib/db.ts
IndexedDB — mastery, srCards, attempts, sessions, plan, profile, settings
```

Content is fetched at runtime rather than bundled, so adding a subject does not grow the JS bundle
and content can be refreshed without a rebuild.

## Engines

| File | Does |
|---|---|
| `lib/sm2.ts` | SM-2 spaced repetition with in-session learning steps at the front. New and lapsed cards cycle within the session before entering the day-based schedule. "Easy" graduates a card immediately. |
| `lib/mastery.ts` | Blends question accuracy, self-rated confidence and recency into a 0–1 score per spec point. Accuracy is shrunk toward 0.5 with little evidence, so one right answer is not read as mastery. Untouched points score zero but are counted separately, so untaught content never reads as "weak". |
| `lib/marking.ts` | Auto-marks objective types exactly; matches short answers against acceptable answers with normalisation and numeric tolerance; proposes partial marks against a mark scheme. Extended and code answers go to self-marking or the AI marker. |
| `lib/planner.ts` | Ranks work as (1) due reviews, (2) weakest studied topics, (3) first pass at new content. Generates each day up to its capacity, and moves missed blocks forward by subject priority, allowing limited overflow before dropping and reporting. Successive days avoid topics already scheduled in the horizon, so the plan advances through the spec. |
| `lib/xp.ts` | XP, levels, streaks with earned freezes, and 15 badges. XP is earned for retrieval and marks, never for time in the app. |
| `lib/ai.ts` | Claude client for explanations, hints and marking extended answers. Enforces a monthly request cap and tracks estimated cost. |

## Why these choices

- **HashRouter, not BrowserRouter.** GitHub Pages serves static files with no rewrite rule, so a
  deep link would 404 on refresh.
- **IndexedDB, not localStorage.** Attempt history and per-spec-point mastery across eleven
  subjects outgrows the 5 MB localStorage ceiling, and structured queries matter.
- **No account, no server.** All progress is local. Backup is a JSON export/import, which is also
  how progress moves between Harry's laptop and phone.
- **Plain CSS with variables, no framework.** One stylesheet, no build complexity, full control of
  the dark theme. The whole thing is under 10 kB.
- **A worker for the API key.** A client-side PWA cannot hold a secret. Direct mode exists for
  local use and is clearly flagged as unsuitable for a shared machine.

## What is deliberately honest

The system is built to avoid the failure mode of the previous one, which was quietly presenting
guesses as facts:

- Unverified specs are badged in the UI, on the subject list and the subject page.
- Unverified resource URLs carry a caution marker rather than being presented as curated.
- Estimated grades say whether they come from real grade boundaries or a rough percentage curve.
- The AI marker's output is labelled as an indication, not a grade.
- The planner reports blocks it had to drop rather than silently losing them.
